プロジェクトに小さな機能を追加しました。しかし、より大規模な変更には、さらに堅牢なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業できるように設計されており、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。Issue から新機能を作成し、コードが有効で機能が期待どおりに動作することを確認して、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能のワークフローを進める間は、同じセッションを使います。通常は作業するファイルの種類ごとに異なるセッションや PR を使いますが、ここでは中心となる概念に集中できるよう、手順を簡略化します。

このレッスンでは、次の内容を学びます。

- GitHub Issue から新しいエージェントセッションを開始する。
- **Plan** モードで要件を定義する。
- **Autopilot** モードを使って新機能を実装する。
- コードをレビューする。
- ブラウザーキャンバスで機能を手動で検証する。

機能の作業を続けながら、リポジトリの指示を更新し、既存の quality-checks スキルをカスタマイズして、MCP による検証を追加し、QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増えてきたため、訪問者はカテゴリやパブリッシャーでゲームを絞り込む必要があります。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで判断事項を整理してから、Autopilot に範囲を限定した実装を許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本はさらに重要になります。多くの開発者は、次のような流れに従います。

1. 必要な作業の詳細が記載された Issue を開きます。
2. 構築する内容の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行し、コードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードのレビューと継続的インテグレーションのプロセスが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや Organization によって異なりますが、多くの場合は上記の流れを調整したものです。

この標準的なアプローチに従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューのプロセスを通るようにします。

## セッションモード

**セッションモード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプトフィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更案を提示し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。エージェントが実行する前に、計画をレビューして承認します。
- **Autopilot**: エージェントが完全に自律してコードを書き、テストを実行し、入力を待たずに反復します。

Plan モードで開始し、計画をレビューしてから、Autopilot で実装します。

## Issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリフォルダーを選択し、リポジトリの上部ナビゲーションで **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートに含まれる既存の Issue なので、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで、New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. Issue がセッションに添付されていることを確認し、モードセレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` の実行を依頼します。ターミナルでは動作するのにセッションで動作しない場合は、アプリの PATH またはバージョンマネージャーの設定を確認し、アプリを完全に終了して再起動します。失敗した操作とチェックを再試行します。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てることで、Copilot がコードを書く前にアプローチをレビューできます。Issue から開始したため、Copilot は機能のリクエストをすでにコンテキストとして把握しています。次を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、Issue の受け入れ基準と計画を照らし合わせます。カテゴリとパブリッシャーによる絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認してください。複数のカテゴリをどう組み合わせるか、一致するゲームがない場合にどうなるかなど、不明確な動作について話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニットテスト、E2E テスト、型チェックを含めます。フィルターの実装とテストに範囲を絞り、品質ワークフローを完了してから PR を作成します。計画の修正は承認前に依頼し、後の検証に使えるよう Issue の URL と合意した補足を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan**、または使用中のバージョンで表示される同等のオプションを選択します。承認しただけでモードが切り替わるとは限らないため、実際のモードを確認します。モード表示が **Autopilot** になっていることを確認してください。

Copilot が実装を開始します。作成した計画に沿ってコードを生成し、テストを実行しながら、作業を反復して進めます。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了と判断する前にセットアップの問題を解決してください。自分が起動したサーバーだけを停止します。

## 実装をレビューして検証する

生成されたコードも、他のコードと同様にマージ前にレビューします。コードを確認し、サイトを実行して問題がないことを確認しましょう。

1. **Changes** を開き、フィルターの実装とテストを確認します。
2. 複数カテゴリやパブリッシャーの組み合わせも含め、結果を Issue と承認した補足に照らし合わせます。変更が既存のリポジトリ指示に従っていることを確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、影響を受けるチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカルサーバーを再利用することがあります。テスト対象が以前のレッスンではなく、この worktree のサーバーであることを確認します。

## 新しい機能を試す

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトで、アプリを起動してブラウザーキャンバスでページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリを選択し、結果がそのカテゴリと一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果がそのパブリッシャーと一致することを確認します。
4. カテゴリとパブリッシャーのフィルターを組み合わせ、結果を Issue と承認済みの計画に照らし合わせます。複数カテゴリに対応する場合は、合意した組み合わせ方を確認します。
5. 一致するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットして、一覧全体が戻ることを確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンのためにセッションを残す

まだフィルターの PR を作成またはマージしないでください。レッスン 4 から 8 まで、同じセッション、worktree、ブランチを使います。次はカスタム指示をフィルターのコードに適用し、スキルと QA の改善を追加してから、レッスン 8 で PR をまとめて作成してマージします。開発サーバーを停止した後はセッションをそのままにし、次のレッスンで同じセッションに戻ります。

## まとめと次のステップ

異なるエージェントモードを使って機能を構築し、レビューしました。このレッスンでは、次の作業を行いました。

- GitHub Issue から新しいエージェントセッションを開始した。
- **Plan** モードで要件を定義した。
- **Autopilot** モードで新しい機能を実装した。
- コードをレビューした。
- ブラウザーキャンバスで機能を手動で検証した。
