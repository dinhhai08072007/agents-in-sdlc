フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストはすべて 1 つのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを管理させます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを円滑に進めるため、フィルター機能と品質ワークフロー全体を 1 つのセッションとブランチにまとめ、この PR に含めます。

このレッスンでは、次の内容を学びます。

- Agent Merge とは何か、マージのライフサイクルを自動化する方法を理解する。
- 機能 PR 全体と検証結果を確認する。
- レビューの後にのみ Agent Merge を許可し、PR がマージされたことを確認する。

## シナリオ

フィルター機能の開発では、Copilot を使って計画、実装、検証を行いました。Tailspin Toys は、マージを許可する権限を開発者が保持したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするまでの残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、CI チェックの失敗を修正し、レビューコメントに対応し、必要に応じてリベースするなど、PR をブロックしている問題に取り組みます。GitHub が許可するとマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその作業を任せられますが、コードの編集やマージには、引き続き明示的な許可が必要です。マージ権限を与える前に、許可する操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わりました。Agent Merge に PR のプロセスを管理させましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンからオプションを選ぶだけでは開始されません。

Agent Merge の処理が始まります。次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- Issue からセッションを開始した場合は、説明の本文で関連する Issue を参照します。
- ターゲットブランチにリベースするか、マージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者または Copilot code review からのフィードバックがないか PR を監視し、コメントを解決するために更新します。
- 必要に応じて、すべてが成功した後に PR を自動的にマージします。

すべてのチェックが成功した後に Agent Merge が PR をマージするように設定します。

5. マージを許可する前に、PR の差分と検証結果をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のように明示的に指示して、エージェントにマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進行状況を確認し、報告されたブロッカーに対処します。続行前に PR の状態が **Merged** であることを確認してください。マージの許可を有効にしたことや、エージェントが実行中であることだけでは、マージ完了の確認になりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前にブロッカーを解消してください。

## まとめと次のステップ

コードの生成、テストと検証、プルリクエストのプロセスなど、開発プロセスの一部を自動化しました。このレッスンでは、次の作業を行いました。

- Agent Merge とは何か、マージのライフサイクルを自動化する方法を理解した。
- 機能 PR 全体と検証結果を確認した。
- レビューの後にのみ Agent Merge を許可し、PR がマージされたことを確認した。
