GitHub Copilot を agent mode にすると、自律的にコードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行される各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または却下できます。また、エディターを離れずに追加のプロンプトを送って会話を誘導し、作業を改善したり拡張したりできます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントを誘導し、ハイコントラストに加えてライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を始める代わりに、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。各ファイルの編集は差分と **Keep**/**Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツール呼び出しの許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業からコンテキストを引き継ぎます。変更したコンポーネント、スタイルの方針、設定を保持するために使ったローカルストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を確認し、ライトモードに必要な変更を提案します。
3. ハイコントラストのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を使います。
4. エージェントが望まない方向に進んだ場合 (たとえば、好みと異なる方法でトグル UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を補足する追加メッセージを送信します。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すよりも速くなります。追加プロンプトで「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」のように調整を依頼したり、「トグルを 3 つに増やさず、既存の設定パネルにライトモードを追加してください」のように修正したり、「両方のトグルにキーボードショートカットも追加してください」のように範囲を広げたりできます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージでの設定保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して誘導しました。ファイル編集を確認しながら、変更を承認または却下し、コンテキストを保ったまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または却下する。
- 追加プロンプトで実行中のセッションを誘導する。
